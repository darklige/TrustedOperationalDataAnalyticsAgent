# 可信运营数据分析 Agent：项目需求

版本：0.1（2026-09-24）
状态：开发基线；完成情况以测试和运行记录为准。

## 1. 项目目标

构建一个可运行、可解释、可评测的数据分析 Agent。用户用自然语言提出运营问题，系统根据明确的数据口径查看数据、执行受控的只读查询、校验结果，并给出带证据的结论。项目同时展示独立实现的 Agent loop、流式交互、工具治理、上下文管理、MCP 互操作和系统化评测能力。

目标用户是分析师或运营人员；演示数据优先采用 [纽约市 TLC 官方公开行程数据](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page)及其区域对照表。数据须固定月份与版本，附下载来源、校验值、建表步骤和数据字典。不得把蔚来业务数据、内部提示词或内部评测集带入项目。

### 1.1 代表性任务

> 某周工作日晚高峰，从机场出发的行程时长为何高于前一周？哪些目的地区域贡献最大？结论是否受样本量、异常值或出发时间分布变化影响？

Agent 应主动识别“晚高峰”“机场”“时长”“前一周”等口径，必要时请求澄清或明确写出采用的默认值。系统给出可复查 SQL、数据版本、结果摘要，以及“观测到的变化”和“可能的解释”的区别；不能仅凭相关性宣称原因。

## 2. 范围

### 必须实现

1. **独立 Agent 运行时**：初始化状态，记录 Trace，进入循环，构建上下文，与模型流式交互，接收并转发事件，解析完整工具调用，执行工具，判断完成/继续/异常，直到终止条件满足。
2. **供应商适配**：核心运行时不依赖 LangChain/LangGraph；模型调用封装在可替换适配器中。测试可注入确定性假模型流，无 API 密钥也能运行核心测试。
3. **工具**：至少提供目录/表结构查询、指标口径查询、只读 SQL 查询。每个工具有稳定名称、JSON Schema 输入、结构化结果、权限及超时约束；本地调用和 MCP 暴露使用同一业务实现。
4. **安全查询**：SQL 仅能读批准的数据对象；执行有行数、时间、内存与并发上限；阻止写入、文件/网络访问、扩展装载和多语句执行。安全校验失败必须返回可诊断的拒绝事件，不交给数据库试错。
5. **结果证据**：每项关键数值和比较都能关联到查询、数据版本、口径定义和结果摘要。引用不能指向不存在的工具结果；不确定性和无法回答必须清楚表达。
6. **Trace 与恢复**：所有状态变更以追加事件保存，保留原始模型/工具轨迹；上下文裁剪或压缩只改变下一次发给模型的视图。至少能按 `run_id` 查询完整轨迹，并从事件恢复最终状态。
7. **流式界面**：CLI 和 FastAPI 的 SSE 接口展现状态、文本增量、工具开始/结束、错误与最终答复；事件顺序可追踪。客户端断开、取消和重试有明确行为。
8. **上下文管理**：预算阈值触发工具结果摘要或会话压缩；摘要要保留任务目标、口径、已验证结论、证据引用、未解决问题。不得删除原始事件或在没有指针的情况下丢弃证据。
9. **Memory 与 Skills**：将二者视为可选、受控的上下文来源。记忆异步提取后只在轮次边界注入；Skills 按需加载，标识版本与来源。二者不能覆盖系统策略、工具权限或数据口径。
10. **评测**：冻结数据与问题集；提供单轮基线、Agent 运行器、确定性评分器、重复 trial、失败分类和结果报告。禁止用测试集调提示词或填造提升数字。
11. **可复现交付**：清晰的环境设置、样本数据准备、启动、演示、测试和评测命令；提供完整示例 Trace 及失败案例。

### 暂不作为首个闭环的要求

多租户、生产 SSO、任意外部数据库连接、自动建模、写回业务系统、前端复杂仪表盘和模型训练。这些功能可在核心质量达标后单独规划，不应阻碍首个端到端演示。

## 3. 功能验收

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| F01 | 基本多轮分析 | 假模型驱动至少两次工具调用并形成最终答复；每次状态转换可从事件复原。 |
| F02 | 流式事件 | CLI 与 SSE 可实时呈现文本增量、工具调用、结果及结束事件；序列号单调递增。 |
| F03 | 工具参数 | 不完整 JSON 不执行；完成事件后进行 schema、权限和预算校验；重复调用不会重复产生副作用。 |
| F04 | 查询安全 | 写入、多语句、未授权表、文件读取、扩展加载和高成本查询被拒绝或受限；测试覆盖变形语法。 |
| F05 | 可核验回答 | 核心事实均附查询和口径引用；查询为空或冲突时不编造结论。 |
| F06 | 上下文管理 | 压缩前后原始 Trace 完整；摘要中的证据 ID 可回查；在低预算测试下仍能继续任务。 |
| F07 | Memory/Skills | 后台提取迟到时只在下一轮注入；不可信内容不能改变策略；加载行为写入 Trace。 |
| F08 | MCP | MCP 客户端可发现并调用项目工具，结果和本地调用语义一致。 |
| F09 | 评测 | 固定任务、数据哈希、模型参数、提示词版本和 trial 结果可重跑；报告不混用开发集与留出集。 |

## 4. 非功能要求

- **可信性**：最终输出包含结论、证据、局限、SQL 和数据版本；缺乏证据时拒绝具体断言。
- **资源边界**：在 MacBook Pro M4/16 GB 上可处理选定的 TLC 数据快照；模型使用可配置 API，核心离线测试不消耗 API 费用。
- **可观察性**：每次运行有 `run_id`、每个事件有 `seq`、每轮有 `turn_id`；关键阶段记录耗时、token/费用（可获得时）、错误类别和查询资源消耗。
- **稳定性**：支持超时、取消、有限重试、最大轮次、最大工具调用数、最大 token/费用预算；终止原因必须明确。
- **安全与隐私**：密钥从环境变量读取且不落入日志；工具结果和 Trace 中可能含敏感数据时做适当脱敏。公开演示只用公开数据。
- **可维护性**：运行时、数据策略、模型适配、传输接口与评测解耦；代码有类型约束和必要的边界测试。

## 5. 评测指标

主要指标：端到端任务完成率、执行结果正确率、关键事实证据覆盖率、越权请求阻断率。辅助指标：平均/分位延迟、模型 token 与费用、每任务工具调用数、重试次数、不同 trial 的波动。对于多种合法 SQL，应以结果和任务完成状态评分，不以 SQL 字符串完全一致为主。

任务集建议 80–120 题，分为口径歧义、多表关联、同期/环比、异常值、空结果、诱导越权、工具错误恢复等类别。先做 10 题小型金标集打通闭环，再扩展；按开发集与留出集分离。所有简历数字必须来自真实运行记录，报告注明样本量、模型、数据快照和运行日期。

## 6. 里程碑与完成定义

| 阶段 | 交付物 | 完成定义 |
| --- | --- | --- |
| P0 | 数据快照、口径、10 题金标、需求与设计 | 任何开发者可复建数据并算出金标结果。 |
| P1 | 最小 Agent loop、事件日志、假模型 | 离线跑通两轮工具调用；Trace 可重放。 |
| P2 | 真实模型适配、CLI、FastAPI SSE | 可以端到端回答样例，流事件顺序正确，断线/取消行为确定。 |
| P3 | SQL 策略与隔离执行 | 安全用例和正常分析用例通过；资源上限实测有效。 |
| P4 | 上下文、Memory、Skills | 长轨迹可继续，原始轨迹不丢失，注入时机受控。 |
| P5 | MCP 适配 | 外部 MCP 客户端发现和调用，与本地工具契约一致。 |
| P6 | 完整评测 | 80–120 题、单轮基线、重复 trial、指标与失败分析可复现。 |
| P7 | 演示与简历材料 | README、架构图、三条完整轨迹、局限与已测数字齐全。 |

每阶段结束必须更新 `docs/teach_me.md`，解释新增模块、实现原因、关键执行路径、如何运行验证、常见问题与面试讲法。
